- Xcode replacement planning should target public external contracts, not Apple private IDE framework ABI parity.
- Credible MVP: Rust-native `xcodebuild` subset plus `.pbxproj` or workspace parsing for macOS arm64 command-line, static library, and simple app bundle builds.
- MVP must fail if flows depend on `DVTFoundation`, `IDEFoundation`, `CoreSimulator`, `XCTest`, or Instruments images.
- External validation context: Docker Compose lane may live outside the repo; Mac-sourced tools or app bundles transferred by wormhole are validation inputs, not runtime dependencies.
- Prefer public AppKit and Cocoa application enablement over extra private Xcode framework startup wins.
- Keep Docker, runtime, and tooling changes biased toward executing native Apple applications end-to-end, especially public Cocoa/AppKit bundles, even when a narrower tool-only win is available.
- Docker-first workaround now has a concrete contract: imported artifacts are described by docker/imported-artifacts.schema.json and mounted as a read-only overlay.
- First native Xcode tool slice shipped in crates/burdettie-xcode-tools: xcrun and xcode-select, with Docker-verified behavior for developer-dir printing, SDK path reporting, opt-in PATH fallback, and invalid switch rejection.
- docker/Dockerfile.burdettie now bakes native xcrun and xcode-select into /usr/bin and smoke-tests them by default when no imported Apple tool overlay is staged; the default /opt/xcode-tools placeholder must not activate overlay mode unless xcode-tc or xcode-dev markers exist.
- Rebuilding docker/macho-inspect-linux-arm64 inside a linux/arm64 Rust container now works after the arm64-translate mincore pointer fix; the refreshed runtime image passes corpus/xcrun_query/app 5/5 with xcode-select state and guest /usr/bin/xcrun subprocesses.
- Initial native xcodebuild slice now lives in crates/burdettie-xcode-tools and is verified in a linux/arm64 Docker Rust container against fixtures/xcodebuild_simple_cli/NativeHello.xcodeproj for -list, -showBuildSettings, build, executable output, and clean; automatic compiler discovery rejects imported overlay toolchains by default and falls back to symbolic SDKROOT=macosx when no real SDK path exists.
- The Docker GUI lane for native Cocoa apps now depends on a gui-enabled docker/macho-inspect-linux-arm64 plus explicit X11/XKB runtime libs in docker/Dockerfile.burdettie; winit otherwise fails at runtime via dlopen with missing libraries such as libXcursor.so.1 even when Xvfb and noVNC are installed.
